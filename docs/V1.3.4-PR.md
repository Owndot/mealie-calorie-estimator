# Suggested PR title

fix: preserve judge provenance and bound estimation concurrency

# PR description

When nutrient generation is disabled, unresolved ingredients lose the judge decision before
Mealie provenance is serialized. Concurrent force-estimate requests also start unlimited
independent pipelines, amplifying network failures during bulk recalculation.

- Retain the existing judge metadata for selected, ambiguous, none, invalid and rejected outcomes,
  including cache hits, through final matched/unmatched provenance. Keep the original match-only
  resolver contract and existing null-verdict convention.
- Bound the shared estimate/webhook/backfill pipeline with `ESTIMATION_CONCURRENCY=2` by default,
  holding the slot through writeback and serializing each recipe slug. Preserve HTTP 202,
  force/manual-protection behavior and failure isolation; do not retry writes automatically.
- Include candidate brand, category, provider and dataset type in the judge fingerprint (`j2`).
  Only judge cache entries are invalidated; no schema migration or manual cache wipe.

Matching gates, provider order, OFF routing/limits and polyol sanity checks are unchanged.
`LLM_NUTRIENT_ENABLED=false` remains supported. Retail consensus and prepared/dry inference are
deferred: current metadata cannot establish them safely. The audit explains local pasta/broth
candidate behavior, the 0.53 branded fast path, completeness tradeoffs and production validation.

Validation: baseline 64 files / 1,274 tests; final full suite **66 files / 1,310 tests**, all passing.
`npm run typecheck` and `npm run build` pass. Compiled-service localhost smoke: health 200,
19 accepted requests, 19 mock writebacks, maximum two active recipes. No real provider calls in
new tests. Docker is unavailable locally; the existing PR CI builds and smoke-tests the image
without publishing it.

Operational limits: the pending queue is process-local, in-memory and not capacity-bounded or
durable; 202 is not completion. Multiple replicas require separate coordination. The package
version remains 1.3.3 for the repository's separate release process. No deployment is included.

See [the full audit](V1.3.4-RESOLVER-HARDENING.md) for root causes, file inventory, compatibility,
risks, deferred work and the post-deployment validation plan.
